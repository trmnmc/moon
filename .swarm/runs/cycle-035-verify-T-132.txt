G2 — INDEPENDENT RECONSTRUCTION BATTERY (cycle-035-gate.js) — the load-bearing check
--------------------------------------------------------------------------------
WHY THIS SHAPE. The mechanism under test is "find the token by scanning for quotes".
A gate that recovers the token the same way proves nothing. So the TRUE token here is
derived by stripping node:util's FIXED sentence templates, measured this cycle:

  ERR_PARSE_ARGS_UNEXPECTED_POSITIONAL  "Unexpected argument '<T>'. This command does
                                         not take positional arguments"
  ERR_PARSE_ARGS_UNKNOWN_OPTION         "Unknown option '<T>'"
  ERR_PARSE_ARGS_INVALID_OPTION_VALUE   "Option '<T>' does not take an argument"

The expected moon message is then RECONSTRUCTED by the conductor from moon's own three
templates and compared byte-for-byte. A template that stops matching fails the gate
loudly rather than degrading silently — so this doubles as the node:util wording pin.

SECOND DISCRIMINATOR: for every positional case the conductor knows the exact string it
passed, so the named token is also compared against the argv element itself. A faked or
degenerate recovery cannot satisfy that — it would have to reproduce an arbitrary input
string it never saw.

31 cases: the 5 T-132 must-change rows, the 13 must-stay-byte-identical rows, and 13
HOSTILE cases the builder never saw (nested/tripled apostrophes, apostrophes with
surrounding whitespace, two apostrophe-bearing positionals, an apostrophe token behind
a valid flag, a backslash token, a Unicode en-dash, `--it's`, `--json='x'`,
`--json=it's`, and two newline-bearing tokens).

G6 — VACUITY READ OF THE SHIPPED TESTS
--------------------------------------------------------------------------------
The 5 behavioral tests assert against LITERAL expected strings, not against a regex
mirroring the implementation — so they cannot pass by construction. The quote-count pin
test calls raw node:util.parseArgs directly and is independent of moon's code entirely;
it is the tripwire that turns a future node:util wording change into a loud CI failure
instead of a silent mis-parse. No test asserts merely that "an error was thrown".

  runtime on this machine. The fix's correctness rests on node:util emitting exactly one

  latter would have been asserting something main never did. Stated plainly rather than
  buried: for a newline-bearing token, moon's usage error is not a single line, and was
  not before this fix either.
