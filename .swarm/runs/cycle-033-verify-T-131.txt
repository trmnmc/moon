C6 + C8 are a matched pair and neither is evidence alone. C8 (fixed README -> all three
green) rules out a test that can never pass; C6 (HEAD's README -> all three red) rules out
a test that can never fail. Standing practice on this run since cycle 32: every battery
carries a control whose answer I already know.

C7 is the discriminator, and it is the check that distinguishes this from a decorative
test. A test asserting only that README's text contains no placeholder would pass against
any well-formed, placeholder-free, BROKEN command. Mutating the documented block to
`node bin/mon.js` (a typo'd path) turns test 1 red and only test 1 -- so the test really
does spawn the command README documents and read its output.

LIMIT, stated rather than buried: test 1 asserts the command's output matches a phase
readout, so a README documenting `echo "  7%  waxing crescent"` would satisfy it without
running the product. That is not a realistic drift for this file (the realistic drift is a
broken or placeholder command, which C7 covers), and closing it would mean asserting
against the binary's live output, which is time-varying. Recorded as a known bound of the
pin, not as a defect it hides.
