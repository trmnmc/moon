T-151 gate, cycle 62 - falsification of the proposed reader check
Proposed check text: 'If your terminal is fine ... bottom-right corner `┘` aligned
under the top-right corner `┐`. If your terminal is affected ... `┘` will be
visibly misaligned with the top-right corner `┐`.'

Method: render the ACTUAL `node bin/moon.js --block` output under both width
policies using Python's unicodedata.east_asian_width (UCD, authoritative offline),
and report the column each line's right-hand border glyph starts at.

EAW class of the frame glyphs:
  ┌ U+250C A
  ┐ U+2510 A
  └ U+2514 A
  ┘ U+2518 A
  ─ U+2500 A
  │ U+2502 A
  -> ALL SIX frame glyphs are Ambiguous. Both border rows are built from the same
     Ambiguous glyphs, so both scale by the same factor.

VERDICT: FAIL. Under ambiguous=2 the top-right ┐ and bottom-right ┘ BOTH sit at
column 66 on 68-column rows - still perfectly aligned with each other. What actually
breaks is the CONTENT rows: their right │ lands at columns 34-37 and is ragged
between rows. A reader in an affected terminal running the documented check would
see the two corners lined up, conclude 'my terminal is fine', and be wrong.
The pre-existing sentence 'the --block frame does not close' remains true; the new
check picked the one part of the frame the failure mode leaves intact.
