G4 — IS IT ACTUALLY A BAND SEARCH? (the whole reason attempt 1 failed)
  Code read at test/regressions.test.js: loops i = 0..BAND_STEPS over
  [max(0, pct/100 - 1/100), min(1, pct/100 + 1/100)], renders each candidate through the
  SHIPPING renderLine, and accepts iff some candidate's RENDERED output matches both the
  row's exact displayed percent and its exact north disc. It never applies a rounding
  rule of its own. Attempt 1 evaluated exactly one point (pct/100).
  Soundness of the +/-1pp bound: candidates are filtered by `samplePct === pct`, so the
  EFFECTIVE searched set is {k in [lo,hi] : renderer displays pct}. For any single-step
  discretization (nearest/floor/ceil) the true display band is a subset of [pct-1,pct+1]/100,
  so the effective set IS the true band, clipped to [0,1]. The superset bound therefore
  widens nothing.
